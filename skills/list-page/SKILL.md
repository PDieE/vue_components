# 列表页面模板

新建列表/表格页面，或调整已有页面的列表、筛选、分页、行操作及状态切换时，应用本技能。业务要求和参考图决定实际字段、顺序、交互及可选模块；遵循目标项目适用的约定。本技能不依赖特定仓库名称、目录布局或业务页面。

## 使用前提与项目接入

- 安装本技能的项目默认已具备下述 `Ui` 系列组件及 `usePaginationData`、`useAsyncAction`、`useStatus` 等对应钩子，直接复用，不将检查依赖是否存在作为前置流程，也不另行寻找替代实现或重复创建组件、钩子。
- 按需读取目标项目已有列表页、组件导出和钩子源码，核对导入方式、类型、属性、事件及数据更新语义；组件和钩子的具体目录可因项目而异，不绑定固定路径。核对实际契约是为了正确接入已有能力。
- 有参考列表页时复用其组织方式，不照搬业务字段、权限标识、接口或文案；没有参考页面时按下述结构组织。

## 页面结构与可插拔模块

默认沿用目标项目现有页面的外层容器及 `UiCard` / `UiCardContent` 组织方式，表格统一使用 `UiDataTable` + `usePaginationData`。不要为复用模板额外封装通用列表容器；除非用户要求，不修改或覆盖已有组件的样式。

以下模块相互独立，按实际需求直接添加或移除，不要求全部出现，也不为省略模块保留空容器、空插槽或占位内容：

| 模块 | 使用条件与接入方式 |
| --- | --- |
| `UiPageTop` | 需要页面标题或描述时使用，已有上层标题或需求未要求时可省略。 |
| `UiFilterForm` | 需要筛选或工具栏时使用；筛选项放在 `UiFilterFormContent`，新增等工具栏操作按需放在 `UiFilterFormAction`。没有筛选项时不创建无意义的表单字段。 |
| `UiPaginationApp` | 需要分页交互时使用；不需要时省略分页 UI，并按实际接口和业务确定数据获取范围。隐藏分页器不等于后端返回全部数据，不得把分页接口第一页当作全量结果。 |

新增/编辑弹层作为独立业务组件，按项目契约打开并传入记录。支持 `useTemplateRef` 且弹层暴露 `show` 时，可调用 `show()` 或 `show(record)`；其他情况沿用已有 ref、受控属性及事件约定。编辑优先传入当前行，没有明确要求时不额外请求详情；成功事件按需要刷新列表。

## 参考表格与缺失字段

- 按参考图保留表格字段、顺序及展示格式。接口未提供的字段，不声明临时字段或扩展行类型，不修改现有接口类型，也不通过类型断言、索引签名或模拟数据伪造字段。
- 缺失字段的单元格使用固定文案“暂缺”，保留参考图对应的文本、标签、颜色及附属文案结构；例如人数显示“暂缺 人想参加”，状态标签显示“暂缺”。同一单元格内接口已提供的数据正常展示，不将真实的空值或关闭状态误判为接口缺失。
- 纯展示列可按现有表格组件契约设置列标识和插槽名；列标识不代表接口字段，不据此读取记录上不存在的属性。
- 完成后在最终回复中逐项总结接口缺失的表格字段，说明其所在列及“暂缺”的展示方式；不能只笼统说明存在占位。

## 数据、筛选和分页

以下为已有组件和钩子的接入方式，具体类型及参数以目标项目源码为准。

- 状态、类型等静态业务映射选项（如 `MapOption[]`）统一声明在目标项目对应业务的映射模块中，由页面导入复用，不在页面内重复声明。新增前先检查已有定义；存放目录、类型名称、命名、注释及导出方式遵循目标项目约定，不固定路径或业务名称。
- 使用业务行类型声明 `DataTableColumn<Row>[]`，按需求配置列；有操作列时沿用 `meta: { fixed: 'right' }` 和合适的列宽。
- `UiDataTable` 绑定 `:data="list"`、`:columns="columns"`、稳定的 `row-key` 及 `:loading="status === 'pending'"`。所有纯文本列都不使用插槽：单个字段原始文本直接配置 `accessorKey`；日期格式化、字典映射、数组拼接、多字段组成字符串及业务说明等仍为纯文本的展示，配置列的 `cell` 回调。只有需要多行排版、标签、图标、组件或交互等结构时，才使用作用域插槽读取 `record`。
- 使用查询结果作为表格数据时，仅做空数组兜底的表达式直接内联到绑定中，例如 `:data="data ?? []"`，不要额外声明 `const list = computed(() => data.value ?? [])`。需要筛选、排序等实际派生逻辑时，再使用计算属性；钩子直接返回的 `list` 可正常绑定。
- 时间类字段没有明确的特殊展示要求时，直接展示接口原值，不进行日期格式化、截断、时区转换或相对时间转换，也不为此添加格式化方法或日期库依赖。单一时间文本列直接配置 `accessorKey`；仅在明确要求时使用 `cell` 实现对应转换。
- 空值、缺省内容及无可用操作的占位统一使用半角连字符 `-`，不使用长破折号 `—` 或短破折号 `–`；接口缺失字段仍遵循前述“暂缺”约定。
- 单一文本列的空值展示交给表格组件统一处理，不在页面添加 `|| '-'`、`?? '-'` 等兜底。多字段组合、业务状态说明及接口缺失字段的“暂缺”占位，仍按各自展示要求处理。
- 筛选状态保存在 `filterForm`，直接传给 `usePaginationData(api, { params: filterForm })`；需要转换时在 `params` 内使用 getter 转换，不另建中间 `params` 变量。无筛选时可省略该配置。
- 先确认钩子是否自动侦听筛选变更；没有自动查询时，输入框 `@change` / `@keydown.enter`、选项 `@change` 以及表单 `@reset` 均按需调用 `refresh()`，回到第一页查询。已有自动查询时沿用其机制，避免重复请求。
- 筛选不展示上方 label，以 placeholder 说明用途；宽度直接设在组件自身；`UiFilterFormContent` 内不加查询按钮。
- `UiPaginationApp` 使用 `v-model:page="currentPage"`（钩子返回的 `page` 别名）、`:total="total"`、`@change="change"`。固定每页条数时，`:items-per-page` 与钩子的 `pageSize` 保持一致，并设置 `:show-per-page-changer="false"`。
- 如需可调整每页条数，先核对钩子的能力：若 `change` 只接收页码或 `pageSize` 不是响应式值，不可假定选择器能自动影响请求。确保选择的条数、请求大小和回到第一页的行为完整联动后再启用。
- 不展示“当前展示 X 条数据”等条数提示，不添加独立错误状态展示分支。
- 筛选变更或需要重置页码时调用 `refresh()`；保留当前页刷新时调用 `refreshCurrentPage()`。删除后应处理当前页变空的情况；仅在确认钩子支持列表长度阈值参数时，使用 `refreshCurrentPage(1)` 处理删除当前页最后一条后的退页。

## 远程行操作：`useAsyncAction`

重置密码、解锁、删除等需要请求接口的行操作，可使用已有的 `useAsyncAction`，避免重复维护请求中状态、当前操作行和防重复提交逻辑。仅打开编辑面板或跳转等本地操作无需使用。以下说明以 `execute`、`actionData`、`isPending` 契约为例，使用前核对实际返回值和并发行为。

- `fn(data)` 执行请求；`execute(data)` 触发操作；`onSuccess(result, data)` 处理成功提示、业务结果及刷新。
- `actionData` 保留最近一次传入的数据；`isPending` 表示该钩子实例正在请求。以 `isPending && actionData === record.id`（传入 id）或 `isPending && actionData === record`（传入记录）定位当前行的 loading，保持比较对象与入参一致。
- 不同操作通常使用独立实例，并按业务命名解构结果，如 `execute: unlock`，避免 loading 相互混用。若同一实例请求期间会忽略重复提交，则其他行的同类操作也会被忽略，交互需与该行为一致。
- 不创建 `busy`、`isBusy` 等合并列表加载和多个操作请求状态的聚合字段。按钮、开关及处理方法直接使用对应操作的 `isPending`、`isMoving`、`isDeleting`、`isToggling` 等状态；列表加载状态仅用于表格 loading，不用 `status === 'pending'` 等列表加载判断禁用行操作或拦截操作方法；可交互的记录允许操作。不要默认让无关操作互相禁用。
- 是否需要 `UiPopoverConfirm`、危险操作主题、权限指令及成功反馈，由业务要求决定；已有权限约束应保留。按业务选择刷新当前页或第一页，不固定照搬示例页的刷新方式。

## 状态切换：`useStatus`

启用/停用等状态切换可使用已有的 `useStatus`。默认优先考虑与 `UiSwitch` 组合，也可按业务使用按钮、菜单或其他交互；仅展示状态时使用 `UiTagMap` 等展示组件，无需接入切换钩子。以下说明以 `toggle`、`toggleData`、`isToggling` 契约为例，使用前核对实际实现。

- `fn(record, value)` 接收行记录和目标状态，按接口要求组装请求；`toggle(record, value)` 触发切换。泛型和实际状态值需匹配业务类型，不默认所有接口都使用数字 `1` / `0`。
- 核对默认状态字段及自定义字段的配置方式；支持 `key` 时可指定其他字段。检查泛型约束，若 `T` 仍要求包含 `status` 字段，不能假定设置 `key` 就能接收任意记录类型。
- 搭配 `UiSwitch` 时，使用 `:model-value="record.status"` 和 `@change="toggle(record, $event)"`，按业务提供 `true-value` / `false-value`，避免通过 `v-model` 在请求成功前提前改写行状态。
- 使用 `UiSwitch` 切换状态时，在开关右侧显示当前状态对应的纯文本，文案与业务状态选项一致；开关与文本横向排列并保留间距，文本从同一个行状态字段派生，随请求成功后的状态更新同步变化。
- 使用 `:loading="isToggling && toggleData === record"` 定位当前行，可用 `:disabled="isToggling"` 禁止同实例请求期间的其他切换，并提供有意义的无障碍名称。
- 确认钩子何时写入目标字段、是否在失败时恢复原值、是否自动刷新列表，确保状态与请求结果一致。`onSuccess` 可添加提示；只有需要同步其他服务端字段、排序或筛选结果且钩子未处理时才额外刷新，避免重复刷新。
- 非开关交互同样传入记录和明确的目标值，并根据 `isToggling` / `toggleData` 接入请求状态。不要同时用 `useAsyncAction` 再包一层同一状态切换请求。

### 可选确认：`UiAlertDialogApp`

按业务要求，可在 `UiSwitch` 切换前使用 `UiAlertDialogApp` 二次确认；可只对停用等特定目标状态确认，也可对所有切换确认，不强制每次切换都弹窗。

- 需要确认时，将开关的 `@change` 接到独立处理方法，保存待操作记录及目标状态，再打开弹窗；不需要确认的分支直接调用 `toggle(record, value)`。
- 使用 `v-model:open` 控制弹窗，通过 `title`、`description`、`confirm-text` 说明操作对象、影响及确认动作；停用等操作可按业务设置 `confirm-theme="destructive"`。
- 仅在弹窗 `@confirm` 中用保存的记录和目标状态调用 `toggle`。继续使用开关的 `:model-value` 单向绑定；弹窗打开、取消或关闭时均不提前修改行状态，也不发送切换请求，状态文本保持原值。
- 弹窗打开期间不覆盖待确认记录和目标状态；处理方法应拦截请求中或已有确认弹窗的重复操作。确认时使用待确认数据，避免重新从当前开关状态推算目标值。
- 核对弹窗确认与关闭事件的时序：确认处理时先取得待操作数据，再按组件关闭流程清理临时状态，避免关闭回调先清空数据导致未提交。弹窗关闭不代表请求成功，请求 loading 和状态更新仍交给 `useStatus`。

## 使用前后检查

仅按任务需要选用模块、钩子和刷新策略，不照搬模板中的具体业务。新增方法添加 JSDoc：有入参时使用多行注释说明用途并用 `@param` 说明各参数；无入参时使用单行用途注释，不添加返回内容注释；目标项目另有约定时按其要求调整。核对接口参数、行唯一键、权限、状态值类型，以及筛选/重置/翻页/操作成功后的数据更新是否接通。
