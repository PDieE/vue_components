# TypeScript 注释规范化

仅规范用户指定范围内的 TypeScript 声明。范围可以是当前选区、指定名称的 `interface`/`type`、指定字段或整个文件。若未说明范围，不要直接修改整个文件；存在选区时优先处理当前选区。

执行最小且安全的编辑。除非命中以下规则，否则保留导出、修饰符、默认值、无关注释、缩进、属性顺序及用户已有的字面量类型。

## 值映射注释

### 括号内的布尔值说明

优先识别单行描述中括号包裹的布尔值说明：括号内同时存在 `false-说明` 与 `true-说明` 两项时（两项之间可用空白、逗号或分号分隔），将括号外文本作为字段描述，并改写为：

```ts
/**
 * 状态
 * @describe false: 下架; true: 上架;
 */
enabled?: boolean;
```

例如 `状态(false-下架 true-上架)` 必须按上例转换。此规则优先于“单行 JSDoc”与“移除可选标记”规则：保持该属性原有的 `boolean` 类型和 `?` 不变，不要生成 `'false' | 'true'`，也不要压缩为单行注释。若括号内不同时包含明确的 `false` 和 `true` 两项，则不适用本规则。

若属性紧邻的前置 JSDoc 能可靠解析为一组取值映射，则：

1. 先将全角分隔符视为其半角等价形式（`：`、`，`、`；`）。接受下列常见且结构一致的写法：

   - `key: description`、`key=description` 或 `key-description`；
   - `key（description）` 或 `key(description)`；
   - `key说明`：键与说明之间省略分隔符。仅在至少两项结构一致、项目之间有明确分隔、每项均能唯一拆分为合法键与非空说明时接受。数字或 ASCII 标识符与中文说明之间的字符类别变化可作为边界依据；不能唯一拆分时跳过；
   - 以空白、逗号、顿号（`、`）、分号、换行、`/` 或 `|` 分隔的多组映射。

   键应为无空白的数字（包括负数）或标识符式值，例如 `-1`、`0`、`submit`、`project_user`。冒号形式可包含一个明确键值对；其它形式必须至少有两个连续、结构一致的键值对。负号属于数字键，不作为键值分隔符。允许混用等价的分隔符，但不能把一个键值对的描述误拆为下一个键值对。

2. 仅在所有候选键值对均可解析且映射段边界清晰时转换。字段描述应取映射段之前或之外的说明性文本；若不存在，使用属性名。不要把 URL、时间、对象示例、公式、单个赋值表达式、普通连字符短语，或包含无法归属文本的内容视为映射。存在两种合理切分方式时保持原样并说明跳过原因。

3. 将声明类型替换为映射键构成的字面量联合类型。数字键为数字字面量（`0 | 1`）；其他键为带引号的字符串字面量（`'pending' | 'done'`）。按文档中的顺序去重。不要推断布尔值、枚举成员或常量；除非键明确是数字，否则使用带引号的字符串。
4. 将注释改写为标准 JSDoc 块：

   ```ts
   /**
    * 字段描述
    * @describe 0: 禁用; 1: 启用;
    */
   ```

   说明性文本与映射值必须分开。映射分隔符统一为 `; `，并保留结尾的 `;`。仅当原注释除映射外没有说明性文本时，才使用属性名作为兜底描述。
5. 若注释已是该最终 `@describe` 格式，则不修改注释或类型，确保重复执行时保持幂等。

例如，以下写法都可转换：

- `操作类型 submit=提交 transfer=转派`
- `状态：0-禁用，1-启用`
- `来源 manual（手动） | system（系统）`

其中第一个例子应改写为：

```ts
/**
 * 操作类型
 * @describe submit: 提交; transfer: 转派;
 */
type: 'submit' | 'transfer';
```

按注释的结构识别映射，不依赖特定字段名、业务词汇或预设键值列表。省略键值分隔符时同样适用上述描述提取、类型转换和 `@describe` 输出规则。没有明确项目边界、键与说明存在多种合理切分，或仅为普通数量说明时，保持原样；不要猜测并缩窄运行时类型。

## 单行 JSDoc

对不属于值映射的普通 JSDoc，先移除开头的 `/**`、结尾的 `*/`、每行开头的 `*` 和首尾空白，再统计剩余的非空有效内容行。若恰好只有一行，则无论原先占用几行，都必须压缩为单行形式：

```ts
/** 本自然月是否可以调整 */
canAdjust: boolean;
```

例如下面三行注释必须压缩，不能仅修改其后的属性声明：

```ts
/**
 * 本自然月是否可以调整
 */
```

含有 `@describe` 或其他 JSDoc 标签、多段有效文本、代码块或列表的注释不适用此规则。不要改写已经是单行形式的 JSDoc。

## 声明清理

在用户指定范围内，除非用户明确豁免某些属性、名称模式或声明，否则应用以下默认规则：

- 将属性类型中的 `Date` 改为 `string`；如 `Date | null`，保留其他联合成员。
- 移除普通属性声明的可选标记（`?`）。
- 移除字符串或数字索引签名，例如 `[property: string]: any;`、`[key: string]: unknown` 与 `[index: number]: T;`。若其紧邻 JSDoc 仅用于说明该索引签名，也一并移除。
- 将名为 `id` 或以 `id` 结尾（大小写不敏感）的属性的 `number` 类型改为 `string`，例如 `userId`、`order_id`、`ID`。仅在有效类型恰为 `number` 时应用；除非用户另有要求，不修改 `number | null` 一类更宽泛的联合类型。

豁免规则优先于默认规则。接受诸如“保留 `createdAt?` 为可选”“保留 `[key: string]: unknown`”或“不转换 `merchantId`”的简短指令。除非用户提供模式，否则字段名豁免应按精确名称处理。

## 安全与完成标准

编辑前先检查选中的声明，区分属性、方法签名、调用签名、映射类型与对象值。属性规则只应用于属性。对于类型别名，以同样方式处理对象形状的成员；不要重塑任意条件类型、映射类型或工具类型。

编辑后检查变更后的声明是否为有效 TypeScript，并在可行时运行最小范围的格式化或类型检查。最终回复中说明已处理范围，以及因歧义而跳过的映射或声明。
